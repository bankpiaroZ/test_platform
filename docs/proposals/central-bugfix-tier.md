# ข้อเสนอ: แยก "แก้บั๊กของกลาง" ออกจาก "เปลี่ยนกติกา"

เขียน: 2026-10-28 · จากเหตุการณ์ PR #3

## เจออะไร
PR #3 แก้บั๊กใน `.github/workflows/deploy-dev.yml` (login ghcr ล้มบน runner Windows)
CI ปฏิเสธเพราะกติกาปัจจุบันบอกว่า "แตะ .github/ = ต้องมีป้าย decision + ไฟล์ใน docs/decisions/"
ทั้งที่ไม่มีการตัดสินใจอะไรใหม่ แค่ทำให้ของที่ตกลงไว้แล้วทำงานได้จริง

## เสนอ
ใช้ขนาดงาน S / M / L (ตามร่าง 10-workflow) แทนการดูแค่ path
- แตะของกลางแบบไม่เปลี่ยนพฤติกรรมที่ตกลงไว้ (แก้บั๊ก, แก้ encoding, เปลี่ยน action เวอร์ชัน) = **M**: คนอนุมัติ 1 คนตาม CODEOWNERS ก็พอ ไม่ต้องมี ADR
- แตะของกลางแบบเปลี่ยนกติกาหรือโครง = **L**: ป้าย decision + ADR เหมือนเดิม
- ผู้เปิด PR ระบุขนาดในหัว PR (`Tier: M`) และ CI ตรวจแค่ว่า L มี ADR จริง ส่วน "ใช่ L ไหม" เป็นดุลยพินิจของผู้อนุมัติ

## ถ้าตกลง
แก้ `ci.yml` ขั้น "แตะของกลางต้องมีป้าย decision" และ PR template พร้อมกับการเอาชุดคำสั่ง `/team-` ลง repo (ซ้อมช่วง 3)
